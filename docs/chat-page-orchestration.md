# ChatPage & Message Orchestration Documentation

`ChatPage` у поточній архітектурі — це **реактивний споживач даних**, який делегує всю бізнес-логіку сервісам та відображає стан чату в реальному часі.

## 1. Підписка на дані (Observable Pattern)
`ChatPage` не зберігає історію повідомлень самостійно. Він лише відображає те, що йому надає централізований `ChatService`.

- **Механізм підписки:** Використовується `useEffect` для підписки на `chatService.subscribe(setState)`.
- **Реактивність:** Кожного разу, коли в `ChatService` змінюється масив `messages` або стан `isProcessing`, сервіс викликає `notify()`, що призводить до автоматичного перерендерингу сторінки.

## 2. Життєвий цикл повідомлення (state.messages)

Наповнення та оновлення стану відбувається в три етапи:

### Етап А: Миттєве додавання (User Action)
Коли користувач взаємодіє з `ChatInput` (текст, файл або камера):
1. `ChatInput` ініціює `chatService.addMessage()`.
2. Сервіс створює об'єкт `Message` з початковим статусом `PENDING`.
3. Повідомлення миттєво з'являється в інтерфейсі (наприклад, як фото-прев'ю).

### Етап Б: Перехід у стан обробки (Processing)
Як тільки запускається `useTaskProcessor`:
1. Викликається `chatService.setProcessing(true)`, що активує глобальний `Loader` на сторінці.
2. Статус конкретного повідомлення оновлюється на `PROCESSING`.
3. В інтерфейсі (компонент `Bubble`) біля медіа-файлу з'являється спінер.

### Етап В: Отримання результату від ШІ
Після успішного завершення аналізу на сервері:
1. `useTaskProcessor` отримує фінальний статус `COMPLETED` та текст відповіді.
2. **Оновлення статусу:** Викликається `chatService.updateMessageStatus(id, 'COMPLETED', content)`.
3. **Зміна типу:** Тип повідомлення змінюється на `ai_result`.
4. **Фінальний рендер:** `ChatPage` відображає `AiResultCard` замість початкового зображення.

## 3. Переваги архітектури
- **Single Source of Truth:** `ChatService` є єдиним джерелом істини для всього додатку.
- **Відокремлення інтересів (Separation of Concerns):** `ChatPage` відповідає лише за UI, `ChatInput` — за вхідні дані, а `ChatService` — за стан.
- **Масштабованість:** Легко додати нові типи повідомлень або джерела даних (наприклад, WebSocket для реального часу), не змінюючи логіку відображення на сторінці.
