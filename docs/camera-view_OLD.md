# CameraView Component Documentation

`CameraView` — це спеціалізований компонент для роботи з апаратним забезпеченням камери, який інтегрований у цикл обробки ШІ. Він поєднує низькорівневе керування медіа-потоками та високорівневу логіку чату.

## Покроковий опис роботи

### 1. Життєвий цикл та доступ до камери
Компонент використовує кастомний хук `useCamera`, який інкапсулює роботу з `navigator.mediaDevices.getUserMedia`:
*   **При монтажі:** Викликається `startCamera()`, яка запитує дозвіл у користувача та активує відеопотік.
*   **Вибір камери:** Параметр `facingMode` дозволяє перемикатися між фронтальною (`user`) та основною (`environment`) камерами.
*   **Відображення:** Потік передається в HTML-елемент `<video>` через `ref`.

### 2. Захоплення зображення (`takePhoto`)
Коли ви натискаєте кнопку зйомки:
1.  Створюється невидимий елемент `canvas`.
2.  Поточний кадр з відео малюється на цей canvas.
3.  Дані з canvas конвертуються в об'єкт `Blob` (бінарні дані зображення).

### 3. Інтеграція з чатом та ШІ
Це найважливіший етап, де відбувається взаємодія з оркестратором:

- **Отримання файлу:** Після `takePhoto` отримується `Blob`.
- **Прев'ю:** Використовується `URL.createObjectURL(blob)` для миттєвого відображення фото в інтерфейсі.
- **Створення повідомлення:** Через `chatService.addMessage` додається нове повідомлення типу `image`.
- **Ініціація аналізу:** Викликається `processFile(blob, messageId)`, що запускає ланцюжок: `Upload -> Polling -> Result`.

### 4. Роль у загальній архітектурі
`CameraView` ініціює весь ланцюжок подій:
1.  **UI:** Закриває інтерфейс камери.
2.  **Global State:** Через `processFile` активує глобальний `isProcessing` в `ChatService`.
3.  **ChatPage:** Отримує оновлення статусу через підписку на `ChatService` та показує центральний `Loader`.
4.  **Backend:** Відправляє файл на сервер, отримує `taskId` і починає опитування (polling).

## Технічні особливості
*   **Миттєвий відгук:** Завдяки локальному прев'ю користувач бачить результат ще до завершення завантаження на сервер.
*   **Керування ресурсами:** Компонент автоматично зупиняє медіа-треки при розмонтуванні, звільняючи камеру та зберігаючи заряд пристрою.
*   **Типізація:** Тісно інтегрований з `ChatService` для переходу стану повідомлення від `image` (завантаження) до `ai_result` (готовий результат).
