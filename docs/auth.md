# Authentication System

Цей документ описує архітектуру та імплементацію системи авторизації в проєкті.

## Архітектурний огляд (FSD)

Система авторизації розділена на кілька шарів згідно з методологією Feature-Sliced Design:

1.  **`shared/api`**: Базовий HTTP-клієнт (Axios) з інтерцепторами для автоматичної обробки токенів та їх оновлення.
2.  **`shared/lib/auth`**: Автономний сервіс `authService`, що використовує паттерн **Observer** для реактивного управління станом авторизації.
3.  **`entities/user`**: Бізнес-сутність користувача, включаючи типи, локальний стан (`userService`) та початкову ініціалізацію профілю.
4.  **`features/AuthByUsername`**: Ізольована фіча, що містить логіку входу (LoginForm) та взаємодію з API.
5.  **`pages/login`**: Сторінка авторизації, що об'єднує компоненти вищих шарів.

## Обробка токенів

Використовується механізм **JWT (JSON Web Tokens)** з двома типами токенів:
- **Access Token**: Короткоживучий токен (15 хв) для авторизації запитів. Передається в заголовку `Authorization: Bearer <token>`.
- **Refresh Token**: Довгоживучий токен (7 днів) для отримання нової пари токенів без повторного входу користувача.

### Алгоритм оновлення (Silent Refresh)
HTTP-клієнт автоматично перехоплює помилку `401 Unauthorized`. Якщо це можливо, він виконує запит на оновлення токена:
1. Призупиняє всі наступні запити.
2. Виконує `/auth/refresh`.
3. При успіху — повторює всі призупинені запити з новим токеном.
4. При помилці — очищує дані, показує сповіщення та перенаправляє на сторінку входу.

## Використання

### Захист маршрутів
Для обмеження доступу до сторінок використовуйте компонент `ProtectedRoute`:

```tsx
<Route 
    path="/admin" 
    element={
        <ProtectedRoute>
            <AdminPage />
        </ProtectedRoute>
    } 
/>
```

### Доступ до даних користувача
Підписка на зміну стану користувача здійснюється через `userService`:

```tsx
useEffect(() => {
    const unsubscribe = userService.subscribe((user) => {
        setUser(user);
    });
    return unsubscribe;
}, []);
```

## API Ендпоінти

| Метод | Шлях | Опис |
| :--- | :--- | :--- |
| `POST` | `/auth/login` | Вхід за логіном та паролем |
| `POST` | `/auth/register` | Реєстрація нового користувача |
| `POST` | `/auth/refresh` | Оновлення пари токенів |
| `GET` | `/auth/me` | Отримання профілю поточного користувача |
