# ChatInput Orchestration Documentation

`ChatInput` є центральним оркестратором інтерфейсу чату. Він виконує роль **адаптера**, який збирає дані з різних джерел (сенсорів), уніфікує їх і запускає процес обробки ШІ.

## Ланцюжки подій за типами запитів

### 1. Фото з камери (Camera Capture)
1.  **CameraView (Сенсор):** Робить знімок, створює `Blob` і викликає колбек `onCapture(blob)`.
2.  **ChatInput (Оркестратор):**
    *   Приймає `Blob` через уніфікований метод `handleMediaReady`.
    *   Створює локальне прев'ю (`URL.createObjectURL`).
    *   Додає повідомлення типу `image` у `ChatService`.
    *   Викликає `processFile(blob, messageId)` для запуску аналізу.
    *   Закриває інтерфейс камери (`setIsCameraOpen(false)`).

### 2. Завантаження файлу (File Upload)
1.  **HTML Input (Сенсор):** Користувач вибирає фото через системний діалог, що генерує подію `onChange`.
2.  **ChatInput (Оркестратор):**
    *   Перехоплює об'єкт `File` у `handleFileChange`.
    *   Передає його в `handleMediaReady(file)`.
    *   Створює прев'ю та додає повідомлення `image` у `ChatService`.
    *   Запускає `processFile(file, messageId)`.

### 3. Голосове повідомлення (Voice Recording)
1.  **useVoiceRecorder (Хук-сенсор):** Керує `MediaRecorder` та збирає аудіо-дані.
2.  **Процес:** Після зупинки запису хук створює `audio/webm` Blob.
3.  **ChatInput & Service:** 
    *   Хук самостійно ініціює додавання повідомлення та виклик процесора.
    *   `ChatInput` реагує на зміну стану `isProcessing` через підписку на `ChatService`, відображаючи глобальний лоадер.

### 4. Текстовий запит (Text Messaging)
1.  **UI:** Користувач вводить текст і натискає `Enter` або іконку відправки.
2.  **ChatInput (Оркестратор):**
    *   Викликає `handleSend`.
    *   Додає повідомлення типу `text` у `ChatService` для миттєвого відображення.
    *   Очищує поле вводу.

## Спільний ланцюжок обробки ШІ

Після того, як будь-який сенсор ініціював `processFile`, запускається стандартний цикл:

1.  **Активація Loader:** `useTaskProcessor` встановлює `chatService.setProcessing(true)`, що вмикає Loader у `ChatPage`.
2.  **Статус повідомлення:** Статус конкретного повідомлення змінюється на `PROCESSING`, активуючи локальний спінер у `Bubble`.
3.  **Polling:** Система опитує сервер щодо готовності результату.
4.  **Трансформація:** Після отримання результату тип повідомлення змінюється з `image`/`audio` на `ai_result`, що перемикає рендер з медіа-файлу на `AiResultCard`.
5.  **Завершення:** Глобальний Loader вимикається, користувач бачить фінальну відповідь.

## Архітектурна роль
`ChatInput` приховує складність обробки медіа від `ChatPage`, забезпечуючи єдину точку входу для всіх типів взаємодії користувача з ШІ-асистентом.
