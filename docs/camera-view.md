# CameraView Component Documentation (Refactored)

`CameraView` — це спеціалізований компонент для роботи з апаратним забезпеченням камери. Після рефакторингу він працює як **"чистий сенсор" (Pure Component)**, що не має власної бізнес-логіки та не знає про існування серверів чи сервісів чату.

## Нова архітектура

Компонент повністю делегує управління станом та обробку результатів батьківському компоненту (оркестратору).

### 1. Життєвий цикл та доступ до камери
Компонент використовує кастомний хук `useCamera`, який інкапсулює роботу з `navigator.mediaDevices.getUserMedia`:
*   **При монтажі:** Викликається `startCamera()`, яка активує відеопотік.
*   **Відображення:** Потік передається в HTML-елемент `<video>` через `ref`.

### 2. Захоплення зображення (`takePhoto`)
Коли користувач натискає кнопку зйомки:
1.  Створюється невидимий елемент `canvas`.
2.  Поточний кадр з відео малюється на цей canvas.
3.  Дані з canvas конвертуються в об'єкт `Blob`.

### 3. Взаємодія через Props (Pure Pattern)
Замість прямого виклику сервісів, `CameraView` використовує колбеки:
*   **`onCapture(blob: Blob)`**: Передає створений знімок батьківському компоненту для подальшої обробки (наприклад, відправки на сервер).
*   **`onClose()`**: Повідомляє оркестратора про необхідність закрити інтерфейс камери.

## Інтеграція з оркестратором (ChatInput)

Тепер ланцюжок подій виглядає так:
1.  **CameraView:** Створює `Blob` і викликає `onCapture(blob)`.
2.  **ChatInput (Оркестратор):**
    *   Отримує `Blob`.
    *   Створює повідомлення в чаті через `ChatService`.
    *   Запускає аналіз через `useTaskProcessor`.
    *   Закриває інтерфейс камери.

## Технічні особливості
*   **Незалежність:** Компонент можна перевикористовувати в будь-якій частині додатку (наприклад, для зміни фото профілю).
*   **Легке тестування:** Оскільки компонент не залежить від API або глобальних сервісів, його легко тестувати ізольовано.
*   **Керування ресурсами:** Компонент автоматично зупиняє медіа-треки при розмонтуванні, звільняючи камеру.
